# 联境 V3.0 · 第一期建设方案与业务原型

在线地址：https://xingyuzhang65-cloud.github.io/new-system/

## 本版依据与范围
依据用户提供的一期边界会议纪要调整原型。录音没有转写或上传到外部服务，本版未声称与录音逐句核对。页面为方案评审原型，不表示功能已在生产上线。

一期：客户管理 CRM、产品管理、资源管理、轨迹管理、订单管理 OMS。
财务：作为并行专项同步梳理范围、费用事件与系统接口，完整交付清单和排期尚待确认。
第二期：仓库运营和关务；部分相关履约细项保留流程参考，具体排期需评审。
客户端：完整重构在内部 ERP 完善后开展，保留现有入口衔接需求。

安速、天图、美仓为不同法人，客户不重合，渠道与仓库资源独立。统一平台与软件能力不改变其数据及账务归属。

## 页面与交互
- 一期建设工作台：范围卡片、五个核心入口、旧系统分工、待决策摘要。
- 范围与实施方案：一期范围、技术与集成、新老切换、决策与行动、流程板块映射。
- 资源主档与旧编码映射展示；轨迹事件示例补录、原始/标准节点及事件 ID 去重。
- 按组织切换演练检查、历史入口配置说明、交付方案本地讨论草案。勾选完整不等于实际验收或切换批准。
- 保留新建订单、法人内搜索与处理日志；后续仓库关务参考页不提供作业推进和新增特殊仓储单。

## 系统过渡与待决策项
基础数据可清洗迁移；历史订单和历史财务原则上留在老系统，并设计查询入口。已有在途单由原系统收尾。新旧系统需明确字段与对象主责，单向事件回流不等于双向写同一字段。
一次性交付或分批交付仍待决策。消息总线、ELK/埋点报表、微服务拆分和部署资源属于候选方案。日志与监控先行，链路追踪可后续完善。会上提及的上线日期和年份不在原型中作为确定排期。

## 运行和验证
Node.js 20+，无需安装依赖：

```sh
npm start
npm test
npm run check
```

默认本地预览 http://127.0.0.1:4206/ ，亦可 node server.mjs 4258 指定端口。GitHub Pages 从 main 分支根目录发布。

## 原型数据与实现限制
所有客户、金额、资源、事件为模拟数据。生产环境须在服务端落实租户隔离、鉴权、字段权限、事件幂等、日志监控与接口验收，本项目未搭建真实网关、中间件或财务服务。公开页面不包含录音、原始会议文件、真实个人信息和真实凭证。
V2 数据键 lj-independent-v2 保留，并补充新模块默认记录；讨论草案使用 lj-plan-draft-v3。仅保存于本浏览器，原型操作不发送至真实业务系统。
